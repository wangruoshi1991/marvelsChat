# 专业会话分派 v1

`dispatch-v1.jsonl` 是22个公开合成案例，覆盖7个有真实工作空间执行器的专业Agent。目标是区分普通咨询、必要澄清与明确交付，保持当前专业身份，不将尚未接入的成图、成片、设备文件解析或3D生成替换成文字任务。

`agents/specialist-dispatch.js` 是版本1提示封装；每个Agent显式声明`dispatch`，已有执行器版本和历史任务模式不变。运行时使用既有dispatch模型配置，输出只允许`reply / clarify / workspace`；后端`validateSpecialistDispatch`再次验证严格结构及当前会话能力。模型不能返回改写目标、Agent身份、权限、引用或代码。自己的私聊历史仅帮助咨询，本次用户原文/明确澄清链与显式素材才进入direct任务。

离线复现：

```sh
node --test agents/test/specialist-dispatch.test.js backend/test/specialist-dispatch-eval.test.js
```

前一套检验真实注册器、提示封装和数据最小化；后一套将固定期望与对抗输出交给生产validator，验证合同及grader本身。**它们没有调用模型，也不计算意图识别成功率。** 固定期望不是模型答复，不能把22个夹具可解析写成22次真实模型通过。

后续真实评测须单独授权，使用同一版本数据集，保存prompt摘要、实际provider/model、原始完整回复、token、延迟、未知调用与费用；不得失败后自动重试或修改期望。没有可比较的旧专业dispatch基线（旧专业消息为chat，旧相册为plan），首次真实运行应建立本协议基线。

准入阈值：全部案例通过严格schema；执行类必须选择当前Agent精确能力，咨询/否定/引用命令/未接入能力不得误建任务；隐式旧方案必须澄清。任一身份、权限、私聊泄露或未经确认保存失败都阻塞该版本发布。中文/英文可见答复及每个rubric需人工复核，不能以总体均值覆盖关键失败。仅22个合成案例，不推断真实用户分布、检索质量、成果质量、延迟或成本达标。

HTTP/PG/Worker、源消息撤回、并发幂等、专业授权、旧相册回执和实际设备入口分别由集成测试与模拟器验收证明；这里不把模型分派质量与系统事务正确性混为一谈。
