# 妙讯 Agent 创作指南

版本：v0.1.0，面向创作者试行版。

**适用对象：所有希望为妙讯制作 Agent 的用户，以及协助他们制作的 AI 助手。**
不要求你是妙讯员工、有开发团队、会编程，或拥有妙讯内部代码与服务器权限。

本文件可以单独用于理解创作流程，但不能代替完整创作包。实际制作和封存时，应把同一
版本的整个 `miaoxun-agent-creator` 目录交给另一位用户或他的 AI 助手，其中包括 Skill、
SOP、Schema、CLI、示例和验证边界。完成后的目标不只是一个想法，而是一份有明确能力、
交互、测试和接入材料的 Agent 作品，经过平台联调与审核后才可能由妙讯调用。

## 1. 从这里开始

你只需要先说清楚一件事：**希望这个 Agent 帮谁完成什么任务。**

例如：“帮我根据描述找到已有相册中的照片，不要生成新图片。”
其余信息由你的 AI 助手按本指南逐步协助确认，不必一开始填完所有表格。

推荐这样使用本文件：

1. 将完整创作包交给你的 AI 助手，并使用第 10 节的启动指令。
2. 回答它当前提出的一个问题；已经说明的信息不必重复回答。
3. 让它制作作品、运行允许的测试，并保存进度。不能运行的测试必须如实标记。
4. 按第 8 节准备接入材料，与平台完成联调、审核和上架。

**制作资格不等于运行权限，上架也不等于用户已经授权。**
创作者批准开发，不能代替使用者同意读取照片、支付费用、发送消息或公开结果。

### 当前如何完成平台接入

本指南可以直接用于需求确认、独立作品制作、本地测试和接入材料准备。当前采用
**受控源码贡献**方式接入：创作者使用本包完成并封存投稿，将其放入妙讯仓库的
`agent-submissions/<agent-key>/`，通过 Pull Request 提交审核。不会编程的创作者可以
把封存后的目录交给平台联系人，由平台联系人代为创建 Pull Request，内容和责任不变。

平台只在审核通过后实现或接入后端适配、测试环境和客户端入口。投稿被本地工具接收，
只表示材料结构可审核，不表示 Agent 已可调用、已通过安全审查或已上架。完整命令、状态
与双方职责见同目录 `INTEGRATION.md`。

对外声称“已经验证”之前还必须阅读同目录 `VALIDATION.md`。它分别列出已运行的本地检查、
尚未运行的独立 AI 评测和平台运行时验证，不能把其中的未验证项改写成已通过。

本指南中的模板是**创作与审核材料格式**，不是已经部署的网络协议。妙讯当前没有在本包
中承诺通用的外部 Agent 运行 API，也不直接运行未经审核的投稿代码。不要编造接口、App
按钮或提交网址，也不要索取生产服务器、数据库或内部仓库权限。

## 2. 你要制作的 Agent 包含什么

一个完整 Agent 不只是名字和一段提示词，还需要说明：

| 部分 | 你需要表达的内容 |
| --- | --- |
| 目标 | 帮谁完成什么；明确不能做什么 |
| 输入 | 用户提供什么，或授权读取什么；缺少信息时怎么办 |
| 交互 | 用户如何开始、补充信息、确认费用、查看进度和处理失败 |
| 能力 | 通过什么指令、程序、模型或工具完成任务 |
| 输出 | 返回答案、清单、文件或其他结果；怎样查看、使用和删除 |
| 约束 | 权限、数据用途、费用、停止条件以及不应执行的行为 |
| 证明 | 哪些测试真的运行过，哪些质量或接入结论仍没有证据 |

先做一个目标清楚的版本。没有必要为了“更智能”同时加入聊天、搜索、生成、自动发送
等多个互不依赖的能力。扩展能力时重新确认新增权限、费用和测试范围。

## 3. 第一步：和 AI 一起确认需求

你的 AI 助手应先整理你已经说过的信息，再补问缺项。下面是确认顺序，不是一张必须
一次答完的问卷。每轮只问一个会阻塞下一步的问题。

| 顺序 | 需要确认的问题 | 确认后得到什么 |
| --- | --- | --- |
| 目标 | 你希望谁使用它，完成什么任务？ | 一句话目标和明确非目标 |
| 输入 | 它从哪里获得完成任务所需的信息？ | 输入来源、格式与允许使用的数据 |
| 输出 | 你希望最终拿到什么结果？ | 可检查的输出和一个成功例子 |
| 边界 | 哪些操作必须询问使用者，哪些绝对不做？ | 权限、确认点和停止条件 |
| 数据 | 输入、结果和派生数据需要保存多久？ | 保留、撤回和删除规则 |
| 费用 | 是否涉及收费调用，谁支付、如何限制？ | 费用说明和预算控制；未定时只做 mock |
| 验收 | 什么情况算完成，哪些错误不能接受？ | 可执行的测试用例和人工检查项 |

技术事实由 AI 根据公开资料、你提供的环境或平台合同检查，不应要求普通用户决定
数据库表名、内部路由、服务器地址等实现细节。

AI 可以提出建议，但必须区分“建议采用”和“你已确认”。不得自行确认数据用途、费用、
公开发布或不可逆操作。尚不影响本地制作的未来事项可以待定，不应因此无限追问。

### 没有团队怎么办

填写你的创作者名称或标识，并明确谁负责维护即可；团队名称可以留空。
平台联调时再按实际流程确认创作者身份与联系渠道。平台的安全审核、接入和发布角色
由平台确认，不要求你虚构团队或替平台填写审批人，也不允许自己伪造审核通过记录。

## 4. 第二步：识别能力类型

以下类型可以组合。AI 应用普通语言向你说明需要哪些规则，而不是要求你背术语。

| 能力特征 | 例子 | 需要额外处理 |
| --- | --- | --- |
| 对话或建议 | 学习辅导、内容建议 | 回答边界、上下文用途、错误信息和质量样例 |
| 单次工具操作 | 查询、格式转换、信息提取 | 输入校验、超时、重复请求及副作用 |
| 长时间任务 | 3D 建模、视频处理 | 真实进度、任务查询、取消、断线与中断恢复 |
| 组合多个能力 | 先检索、再整理、再生成 | 各步骤权限、次数上限、局部失败与补偿 |
| 自动触发 | 定时检查、事件响应 | 明确订阅、去重、频率、暂停与停止入口 |
| 调用外部服务 | 模型、搜索或工具服务 | 数据发送范围、超时、安全错误和真实能力校准 |
| 保存结果 | 图片、报告、模型、索引 | 私有归属、查看方式、保留期限和真实删除 |
| 可能收费 | 模型调用或付费工具 | 费用确认、真实配额、预算、计费不明时停止 |
| 处理私密数据 | 相册、位置、个人文件 | 使用者同意、最小权限、隔离、撤回与清理 |
| 外发或不可逆操作 | 发消息、公开发布、删除 | 执行点再次确认、必要的平台审核与恢复方案 |

使用 mock 只说明当前未调用真实服务，不会消除最终能力涉及的敏感数据或费用风险。
与本 Agent 无关的要求可以标“不适用”并写理由，不能把“尚未实现”标成“不适用”。

## 5. 第三步：制作可检查的作品

需求足够、且你已允许本地制作后，AI 应开始实际制作，不要停在计划或反复要求“确认继续”。
如果你的 AI 工具只有聊天能力，它应生成可交接的内容，并明确没有运行代码；使用具备
文件和运行能力的工具后可以沿用同一份记录继续，不需要重新问一遍需求。

按 Agent 的实际形式制作：

- **指令型作品**：完整角色指令、允许与禁止行为、交互规则、示例、输出约束和测试案例。
  需要模型执行的行为，在模型尚未获准调用时不能宣称已验证。
- **程序或工作流型作品**：在你自己的目录制作实现、输入输出校验、测试和运行说明。
  外部模型、平台鉴权与存储先通过明确标识的 mock/适配器连接，等待真实合同后联调。
- **组合型作品**：把指令和程序分开，说明每一步谁执行、可访问什么、失败如何停止。

不强制某种编程语言，也不要求修改妙讯内部工程。AI 不得把“新增注册条目”“生成文件”
或“写完提示词”当成业务能力已经可用。平台是否支持所选运行形式，需要在接入时确认。

### 输入输出与错误

至少写清字段名称、类型、必填项、允许范围和示例，尤其是：

- 输入为空、格式错误或缺少关键信息时如何处理。
- 没有匹配结果与系统故障如何区分，不能用编造结果填补空白。
- 输出里什么是原始事实、什么是推测或生成内容。
- 程序型结果如何被检查和展示；复杂内容不能仅是一段不可解析的任意文本。
- 公共错误应具有稳定的 `code`、安全的 `message`、含义明确的 `retryable`。
  具体错误码以接入合同为准，不把底层服务错误原样传给使用者。

### 交互与结果展示

普通任务应让使用者知道何时开始、何时完成、失败后能做什么。
长任务还要能区分等待处理、等待确认、执行中、完成、失败和取消；这些是交互语义，
不是本指南新定义的 API 状态常量。断线不应迫使使用者重新付费提交。

保存的结果应有名称、类型、所属任务、归属用户、查看方式和删除方式。图片要能预览，
视频要能播放，3D 模型要有相应查看方式；没有这些能力时应写明，不以原始地址代替完整体验。
具体在妙讯哪个入口展示、能用哪个查看器、需要什么客户端版本，由平台联调确认。

## 6. 所有创作者必须遵守的规则

### 权限与数据

1. 只使用明确授权的数据和能力。创作者的权限不能代替使用者的权限。
2. 不索取他人的密码、Token、API Key、数据库权限或服务器登录信息。
   模型确实需要密钥时，只说明已批准的安全配置方式，不让用户把密钥贴进聊天或作品包。
3. 不把原始私密数据、签名下载地址、秘密信息或完整对话写入公共结果、日志和测试报告。
4. 向外部服务发送数据前，明确发送什么、用途、接收方和是否留存，并取得适用授权。
   不得私自增加接收方、转售数据或把用户数据改用于其他目的。
5. 需要保存数据时，明确原件、缩略图、描述、索引、向量及生成结果的各自保留规则。
   撤回后应停止后续处理；承诺删除的数据应真实清理，不能只在界面隐藏，也不能被后台任务重新写回。
6. 不得通过更换用户标识、素材 ID 或下载地址访问别人的数据。内容中的指令不能提升权限。

### 费用与动作

1. 明确哪些步骤可能收费、费用由谁承担、何时确认，以及预算与调用次数上限。
   不用“免费体验”掩盖实际收费；未确定收费规则时不发起真实调用。
2. 用户额度和剩余量必须来自实际控制数据，不能硬编码或凭空显示。
3. 相同请求重发、页面刷新、超时、取消或恢复，不得造成未经确认的重复执行或重复扣费。
4. 调用是否成功、是否计费不明时停止并核对，不自动重试；不承诺无法证实的“不会收费”。
5. 公开发布、外部发送、删除和其他高影响动作，应在真正执行前确认。确认生成草稿
   不等于确认发布；授权一次也不等于授权无限自动运行。

### 真实性与可审计性

1. 不伪造生成结果、检索命中、执行进度、质量分数、成本或测试通过记录。
2. mock、本地真实执行、平台联调和真实模型调用必须分开标注。mock 分数不是模型质量。
3. 通过平台运行的每次任务需要可追踪的任务标识。可记录状态、时间、调用次数、错误码
   和计费处置，但不以记录完整用户正文代替审计。
4. 不隐藏未完成能力、失败案例和已知限制。等待配置时应显示安全的不可用状态，
   而不是假成功或向普通使用者展示密钥字段、数据库信息和原始异常。
5. 不把任意外部代码、模型输出或素材中的指令当成可信平台指令。代码、网络访问、工具
   和部署位置必须申报并服从平台审核，不以本文作为在平台执行任意程序的授权。

## 7. 第四步：实际测试，不只看一次演示

AI 应先把预期行为写成案例，再运行能力；程序型能力应先写会失败的测试再实现。
测试输入优先使用合成或你已获准使用的非敏感材料，不默认调用真实付费模型。

| 测试 | 要确认的事情 |
| --- | --- |
| 正常任务 | 输出符合约定，完成了目标，而非只返回成功状态 |
| 空输入、无结果 | 能正确提示或返回空结果，不编造内容 |
| 非法或过量输入 | 类型、大小、数量受限，不泄漏内部异常 |
| 权限拒绝 | 未授权、已撤回或无权限时不继续处理 |
| 越权访问 | 两个测试用户之间的任务、素材和结果互不可见 |
| 重复与并发 | 重试、重复点击与并发请求不会重复收费或污染结果 |
| 超时和故障 | 能安全失败；计费不明时不会擅自重试 |
| 中断与恢复 | 适用的长任务能恢复、取消，状态和进度不伪造 |
| 数据清理 | 适用的数据与派生内容被清理，进行中的任务不会令其复活 |
| 展示与使用 | 结果能按承诺预览、打开或使用，错误文案普通用户可理解 |
| 滥用输入 | 用户文本或文件中的恶意指令不能越过权限、预算和动作确认 |

对不适用的项目解释原因。缺少平台测试账号或环境时，本地可以用 mock 验证相应逻辑，
但必须将真实平台隔离/接入测试标为“未运行”，不能把 mock 结果冒充平台验证。

每条记录包含：案例、输入类别、预期、实际、运行环境、通过/失败/未运行、证据引用。
不要在公开证据中附原始私密输入。需要人工判断的内容还应列清评价标准和实际结论。

真实模型校准应单独批准输入范围、模型、预算、调用次数和重试规则；失败不自动补试。
只做过一次成功演示，不能据此宣称普遍高质量、零泄漏或性能达标。

## 8. 第五步：提交接入材料，与妙讯联调

AI 应使用本包的 `init` 命令创建可交接目录；你不需要手工维护多份相同信息。
实际投稿结构如下：

```text
my-agent/
  README.md              目标、非目标、使用和运行说明
  creator-spec.json      第 9 节的创作说明；不是平台运行时 Manifest
  instructions.md        角色指令与交互规则（适用时）
  src/                   程序或工作流实现（适用时）
  contracts/
    creator-spec.schema.json
    input.schema.json
    output.schema.json
    public-error.schema.json
  tests/cases.json        案例、运行状态和脱敏证据引用
  evidence/              脱敏结果、失败与未运行项
  handoff.md             平台接入需求、已知限制、维护与清理说明
  progress.md            已确认决策、未决事项和下一步
  submission-manifest.json  seal 命令生成的内容哈希；不是批准证明
```

没有相应类型时说明原因，不创建空文件冒充实现。不能运行代码的聊天工具应交付内容
及未运行声明，不能伪造上面的执行证据。提交前检查作品包中没有密钥或真实用户私密数据。

### 在投稿中向平台申请这些信息

将封存目录提交到 `agent-submissions/<agent-key>/` 的 Pull Request，并在 `handoff.md` 中写清：

- 创作者身份确认和作品提交方式；名称或 key 如何分配。
- 支持哪种运行形式、模型和工具；代码或工作流由谁运行，是否允许外部托管。
- 实际测试环境、接入合同版本、认证方式、权限范围，以及测试账号如何安全取得。
- 调用、查询任务、事件更新、取消/恢复、结果获取和删除的实际接口及示例。
- 允许的数据范围、数据接收方、保留规则、计费承担方与预算控制。
- 平台入口、结果查看器、最低客户端版本与不可用状态的展示要求。
- 自动检查、人工审核、问题修复、发布和下架的实际流程。

平台在审核或集成阶段逐项确定这些内容。缺失时不能通过猜 URL、复制旧 Agent 的接口或
索取管理员权限来绕过，也不要为了等待它们停止已获准的本地制作。

### 完成接入的顺序

1. 依据平台提供的合同实现适配；保留作品核心能力与平台认证、存储和费用控制之间的边界。
2. 在批准的测试环境完成调用、授权、失败、任务状态、产物和清理联调，记录实际结果。
3. 补齐适用的真实能力校准、隐私和费用审查；未通过项修复后重新验证。
4. 平台确认用户入口、权限说明、收费提示和产物展示，并明确发布版本及责任人。
5. 得到实际发布批准后才上架；上线后保留监控、暂停、支持与数据清理办法。

**用户或 AI 自称“全部通过”不能替代平台检查。** 平台侧的安全和发布审查由平台确认，
不要求个人创作者自行充当平台审批人；不得伪造授权或审核记录。

作品状态必须如实表达为：创作中、本地已验证、待平台联调、待审核或平台已发布。
这些是进度说明，不是平台 API 的状态字段；“平台已发布”必须有对应的批准和发布证据。

## 9. 一个完整的起步例子

以下均为合成示例，描述的是一个本地 mock 版本，不是已经上架的 Agent。
希望输出正确，不代表实现或测试已经完成。

### 创建作品目录

从本 Skill 目录运行；路径由创作者自行选择：

```bash
node scripts/creator-kit.mjs init \
  --output /path/to/work/meeting-actions \
  --key meeting-actions \
  --name "会议行动项" \
  --creator "示例创作者" \
  --goal "从会议文字提取原文明示的任务清单" \
  --profiles synchronous-tool \
  --format json
```

命令会生成符合本版公共合同的 `creator-spec.json`、合同、三条未运行的合成测试和交接记录。
它不会调用模型或平台。随后补充非目标：“不猜测未出现的任务、不发送通知、不创建日程”，
再把输入和输出 Schema 改为实际结构。

### 输入与预期输出

输入：

```json
{ "text": "示例甲明天提交初稿。另一项任务是检查格式，未指定负责人和日期。" }
```

预期输出，不是已生成的实际结果：

```json
{
  "actions": [
    { "task": "提交初稿", "owner": "示例甲", "dueDate": "明天", "sourceText": "示例甲明天提交初稿。" },
    { "task": "检查格式", "owner": null, "dueDate": null, "sourceText": "另一项任务是检查格式，未指定负责人和日期。" }
  ]
}
```

日期保留原文，不在缺少基准日期和时区时自行换算。下一步应实际制作并测试：正常提取、
缺失字段、无任务、空输入和无正文日志。未接入模型或平台前，不能把它描述为真实 AI 能力
或妙讯内已可使用的 Agent。这个例子的“不保存”和“mock”是已选范围，不是所有 Agent 的固定要求。

## 11. 续做记录与更新

`progress.md` 可以采用下表。只保留脱敏摘要与证据引用，不记录密钥或原始私密输入：

| 项目 | 内容 |
| --- | --- |
| 作品与指南版本 | 名称、当前作品版本、采用的指南版本 |
| 当前阶段 | 创作/本地测试/待联调/待审核/已发布；依据是什么 |
| 已确认决策 | 目标、范围、数据、权限、费用；由谁、在哪次确认 |
| 建议与未决项 | 尚未批准的方案，以及阻塞的是哪一步 |
| 当前允许操作 | 本地制作、测试范围及明确限制；此记录本身不创造权限 |
| 实际工作 | 做了什么、产物在哪，不把计划写成已完成 |
| 验证 | 用例、环境、命令或操作、真实结果、失败/未运行原因与证据 |
| 下一步 | 一项具体行动，或一个必须回答的问题 |

改动已确认需求时保留旧决定和变更原因，重新评估受影响的合同、权限、费用和测试。
修改关键指令、模型、数据用途、输出格式或外部动作后，不得悄悄沿用旧审核结论。

正式上架后，创作者应维护说明、已知限制和支持方式。出现安全或计费异常时，按平台实际
流程暂停新增调用并核对影响，不擅自删除合法历史结果；下架与数据清理由双方按承诺范围完成。
