# 3D 形象创建与结果恢复

Web 使用 `/api/avatar-3d` 和私有会话 cookie，RN 使用 `/api/avatar-3d/app` 和 Bearer 认证。以下路径相对各自入口。

| 请求 | 行为 |
| --- | --- |
| `POST /jobs`，带 `Idempotency-Key` | 创建当前用户确认的四视图任务。首次创建返回 201，同一账号相同键的已创建任务返回 200。创建和绑定照片在同一事务中完成。 |
| `GET /jobs/submission`，带原 `Idempotency-Key` | 返回 200 和 `{"data":{"job":…}}`，包含该账号该提交的任务，包括已结束任务。查不到时返回 `{"data":{"job":null}}`。响应为 `private, no-store`。该查询只读 PostgreSQL，不提交或推进供应商任务。 |

创建回执丢失时，用原键查询。返回空只反映读取时刻。保留原照片 ID、参数和费用确认版本，供用户主动重试。后台出现另一条活动任务不能确认本次提交。确认过的任务随后刷新失败时仍应显示已收到的任务。

Web 在发出创建请求前把账号 ID、原幂等键和原请求参数写入本标签页的 sessionStorage。上传文件、上传地址和会话凭据不写入该记录。同一标签页刷新后，服务端确认登录账号后按原键查询；查询本身不会重新创建。确认回执、退出、会话失效或账号不符时清理记录。关闭标签页会结束该页的恢复能力。RN 在钥匙串中按用户恢复，历史记录缺少费用版本时，原键查不到任务后重新向用户展示当前费用。

## Web 进度与四视图确认

待确认阶段使用 `GET /jobs/:id/references` 读取该任务的四视图。首次读取失败时会显示原位重试和可用的安全请求编号，重试只发起同一个 GET。收到当前任务的完整四视图后，用户明确选定生成精度并确认才可开始 3D 建模。轮询和前台刷新按任务与请求世代接收结果，取消开始时作废在途读取，取消失败会显示原因状态并保留可用的取消按钮。系统减少动态效果开启时，进度图标保持静态，读取和进度文字可供辅助技术读取。

## 供应商提交与私有对象清理

迁移 062 为每次后台领取记录私有令牌和数据库租约。四视图与模型各自在发起供应商请求前提交 `submitting_references` 或 `submitting_3d`。同一次领取持续续租至回执写入。其他实例只领取已过期的提交并将其转为 `submission_unknown`，旧实例回执由令牌与到期校验拒绝。供应商回执明确失败时记录失败。费用或任务 ID 未知时保留未知结果，后台不会自动重新生成。令牌、供应商 ID 和对象键保留在服务端。

到期的照片原件、规范化照片和生成的参考图按各自对象键清理。仅成功删除的对象会清空私有引用。每次失败单独记录安全错误码和重试时间，从五分钟开始递增至一小时，之后重新领取。实例重启后可继续处理，单个失败对象不会阻塞同批及后续对象。
