# 普通聊天消息转发

`POST /api/threads/:threadId/messages/:messageId/forward` 使用 Bearer 会话鉴权。路径中的会话和消息 ID 来自当前账号可读取的本地副本。请求正文只接受两个 UUID 字段。

```json
{
  "targetThreadId": "11111111-1111-4111-8111-111111111111",
  "clientMessageId": "22222222-2222-4222-8222-222222222222"
}
```

首次发送返回 HTTP 201，重复提交相同来源、目标和请求键返回 HTTP 200。两者均返回 `{ "data": { "messages": [MessageDTO] } }`，其中包含发送者在目标会话中的消息副本。消息的 `metadata.forwarded` 为 `true`，发送者身份为实际转发人。服务端只从源消息复制原始正文、图片、录音、视频和文件。原引用快照、原会话或源作者标识不在回执中。

来源与目标仅限单聊和群聊。已退出群聊的成员仍可转发自己可读取的历史。目标群聊要求当前成员资格，目标单聊要求双向好友关系及可用的对方账号。已隐藏或撤回的来源、Agent 和系统消息、贴图、位置、名片、任务卡和创作预览均不接受新转发。

附件转发复制已存储的字节到新附件记录，计入转发人的附件额度。新附件与目标消息及各接收者副本在同一数据库事务内提交，下载沿用消息引用鉴权。目标接收者只获得新附件下载权限。同键重放会恢复当前的目标消息回执，无需再次读取原消息。转发已提交后，来源的删除和撤回只影响来源，目标转发可由转发人在既有撤回窗口内单独撤回。

同一账号用同一请求键更改来源或目标会收到 HTTP 409。客户端收到可重试的连接错误时可用原键再次提交。每个账号每小时可请求此端点 60 次，超过限制时返回 HTTP 429 和 `Retry-After`。

## 多选转发

客户端在原会话已加载的内容中提供最多 20 条可转发消息，按原顺序对同一目标逐条调用现有端点。选择和目标确认先在本机完成。确认后每条请求都有独立请求键、结果和重试入口。确认成功的条目不会随失败条目一起重发。

## 视频附件

支持视频的后端在鉴权后的 `/api/app/bootstrap` 和 `/api/app/sync` 返回 `chatVideoEnabled: true`。普通私聊和群聊沿用消息附件接口。上传使用 `POST /api/threads/:threadId/attachments/upload`、`X-Miaoxun-Attachment-Kind: video` 和 `X-Miaoxun-Attachment-Mime: video/mp4`。接受扩展名 `.mp4`、单条 H.264 视频轨及可选的单条 AAC 音轨，上限 8 MiB 与 60 秒。服务校验容器、轨道声明和时长，播放由系统解码器完成。其他编码和容器暂不可用。

迁移 `073_chat_video_attachments.sql` 扩展附件类型并保留已有字节和类型约束。服务从引用及会话权限授权每次下载。双端播放器只读取短期的 App 私有副本。关闭预览或退出会话时取消下载并清理副本，播放 URL 无账号令牌。转发后的新附件遵循本文的独立副本和撤回规则。
