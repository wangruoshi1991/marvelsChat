# Demo 迁移计划

## 已完成

- 将原始 Demo 的 `index.html`、`styles.css`、`app.js` 迁入历史原型工程，现已移除。
- 新增 `backend/`、健康检查、注册登录、登出、会话、消息、事件和后台管理接口。
- 新增 `agents/` 和第一个 `妙讯管家` Agent。
- 新增数据库 schema：用户、资料、会话、消息、事件、Agent 运行记录。
- 移动端聊天列表、登录注册、小站基础用户资料已接入 `/api/app/bootstrap`。
- 消息发送会写入 `chat_messages`，绑定 Agent 的会话会写入 `agent_runs`。
- 新增 `admin/` 作为独立后台管理系统前端。
- 后台已支持账号创建、详情查看、资料编辑、用户启用/停用、角色调整、登录态撤销、Agent 授权和密码重置。
- App 设置页已接入退出登录，登录页不再提供后台跳转。
- App 已恢复 Demo 的核心模块骨架；未建表模块保留入口和空状态，但不再填充前端假数据。
- App 已将默认视觉校准回原 Demo 的浅色长屏比例、紧凑卡片、小站头像舞台、粘性内容切换和两栏底部导航；“妙”中枢已收敛为底栏中央的小型全局入口。
- 登录后的小站模块已按 Demo 的漫画日记、相册、音乐菜单、可调用 Agent 和动态卡片形态展示真实空状态。
- 消息页保留聊天/通知角标；聊天列表只展示数据库中真实会话，不再用 Demo 假消息填充空白，也不再插入解释性统计卡。
- 小站 Agent 区和 AI伙伴页已收敛为同一套轻量 Agent 名字标签，真实已授权 Agent 优先展示，未授权位置明确显示为待接入。
- 站内“妙”中枢是当前唯一的全局 AI 入口；不再保留重复的站内悬浮 Agent 入口。
- 妙讯页左上角 `+` 菜单已从顶栏内部气泡调整为手机壳级浮层，点击外部、打开弹层或触发模块都会自动收起。
- 妙讯管家聊天页已按 Demo 的抽屉模型重排为头部、独立滚动消息区和输入栏，头像、名称、时间与消息正文使用固定网格对齐。
- 妙讯聊天列表头像文字已统一使用固定尺寸、单行行高和居中网格，避免中文标识在头像内偏移。
- 小站设置入口已替换为明确的设置滑杆图标；AI ID 支持复制，动态码弹层会按当前 AI ID 生成两分钟有效的标准 QR Code，有效期结束或用户手动刷新时才更新二维码内容。
- 浅色/深色视觉已从小站扩展为 App 全局偏好，登录、妙讯、聊天、小站、AI伙伴和设置页共享 palette。
- 小站内容切换栏保留在小站资料下方，并在上滑到顶部后吸附。
- 全局“妙”中枢入口已限制为小站页显示，并上移到导航栏上方；进入动态发布页时自动让位给发布按钮。
- 登录/注册弹层已重排为账号说明、模式切换和表单面板；设置弹层已重排为账号卡、显示、空间与权限、数据和账户分组。
- Agent 运行时已支持 New API 配置；未配置时记录 `not-configured`，不伪造 token。

## 下一步

1. 真实模型接入
   - 在 `backend/.env` 配置 `NEW_API_BASE_URL`、`NEW_API_KEY`、`NEW_API_MODEL`。
   - 验证 `agent_runs` 是否写入真实 provider、耗时和 token。

2. 业务表补充
   - 内容发布：posts、media_assets、post_audits。
   - 个人站点素材：station_assets、station_templates、generation_jobs。
   - 长期记忆：memory_items、memory_sources、memory_consents。
   - 关系与互动：contacts、follows、interaction_events。

3. Agent 接入
   - 继续逐个实现活动搭子、接单助理、二手出售、收藏整理等 Agent。
   - 每个 Agent 独立放在 `agents/`，前端只通过后端 API 使用。

4. 前端工程化
   - 当前先保留轻量 HTML/CSS/JS；下一阶段建议迁移到 Vue 3 或继续拆分模块。
   - 新增页面前先确认后端表、接口和权限策略已经存在。

## 需要注意

原 Demo 里有大量示例聊天、示例 Agent 和示例用户数据。当前 App 保留这些模块的产品位置，但内容改为后端模块状态、真实数据或空状态。未建表的动态、文件、社交、长期记忆等模块必须先补数据库和 API，再把空状态替换为真实内容。

当前 `admin/index.html` 已使用 `type="module"` 引入脚本，Vite 生产构建会输出对应 JS 产物。后续组件化时，仍建议继续把 `admin.js` 拆成更小模块，或迁移到 Vue 等框架入口。
