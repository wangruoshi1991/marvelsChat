# 页面动作统一与显式数据迁移

本轮用户选择保留现有页面及其动作，完善统一结构后迁移。候选已实现严格的页面动作合同、移动端展示和独立迁移工具，并通过真实隔离 PostgreSQL 验证。**生产仍未执行页面迁移或本轮配套部署**；下述发布步骤是待执行方案，不是历史操作授权。

## 保存的是页面意图

正式页面合同仍为 `siteDocuments:2`、`schemaVersion:2`，没有另增产品版本或 v1 运行时兼容入口。页面及模块保留稳定 ID，旧页面由独立操作工具一次转换；API 和 App 只接受当前严格合同。

原有 `view-media` / `view-diary` 继续要求目标属于本模块的精确资源引用，同类目标不得重复。新增动作是未接通的交互意图：

```json
{
  "kind": "interaction-intent",
  "intent": "open-link",
  "label": "链接",
  "target": { "kind": "unresolved", "text": "用户明确提供的目标原文" }
}
```

`intent` 只允许 `open-link`、`compose-message`、`follow-user`。`label` 是 1–40 字符的纯文本，目标是至多 2048 字符的纯文本；空目标保留为空。嵌套对象严格拒绝额外字段和其他目标状态。目标不去空格、不截断、不解释为 URL 或用户身份；允许按作者顺序保留重复意图，不改变资源动作的去重规则。

App 展示动作名称、可选择复制的完整目标文本，以及“尚未接通”状态。按钮禁用且没有执行 handler；不会打开链接、发送消息或关注用户。既有页面此前只显示这些动作的标签，本次不会把历史描述自动升级为已授权的执行。建站 Agent `0.3.1` 使用相同结构，禁止编造目标、自行补充未要求的动作或声称服务已接通。本人页面投影保留意图；他人依旧不能读取这些私有生成页面。

## 迁移范围与保护

实现入口为 [迁移核心](../../backend/src/site-document-migration.js)、[命令行工具](../../backend/scripts/migrate-site-documents.js) 和 [集成测试](../../backend/test/site-document-migration.test.js)。这是显式数据操作，独立于新增协作表的 `037_agent_workspaces.sql`。

最近一次生产只读预检结果：

| 项目 | 数量 |
| --- | ---: |
| 模型来源页面草稿 | 6 |
| 可转换的 v1 草稿 | 6 |
| 当前应用的 profile 页面副本 | 3 |
| 可转换的当前副本 | 3 |
| 完整保留的动作 | 15 |

预检验证通过，只输出汇总；没有保存含生产页面原文的迁移计划，也没有生产写入。

转换规则为 `link → open-link`、`message → compose-message`、`follow → follow-user`，原 `href` 逐字进入 `target.text`。正文、模块顺序、资源引用、动作顺序及重复项均保留。页面 ID 使用原草稿 ID，模块 ID 从迁移标识、草稿 ID 和模块序号确定性生成，重跑不会分配新 ID。不可表示的旧字段、超界文本、无效引用或不一致副本会阻止整个计划，不删除、不截断、不跳过异常页面。

工具读取草稿完整行及持有当前页面的 profile 完整行。当前副本必须属于同一用户，指向未删除、已应用的同一草稿，且副本内容与草稿一致。事务只改草稿 `draft` 和 profile `station_config.siteLayout`；草稿状态、来源、模型信息、其他 profile 内容和微秒级时间戳保留，不调用“应用草稿”业务接口。

`plan` 在可重复读、只读事务中读取统一快照，并检查每个未删除页面的资源归属、未删除状态与媒体已上传状态。`apply` 再次检查这些条件并在事务内锁定所读资源。**计划没有冻结资源内容版本**：它验证引用仍属于本人且可用，不保证素材或日记内容与计划时完全相同。正式预览仍通过现行完整资源读取与 hash 合同验证。

计划包含数据库连接身份、转换前后完整快照、汇总和 SHA-256。工具不仅比对 hash，还重新计算合法转换，防止修改原始快照后仅重算摘要绕过校验。`apply` / `restore` 仅接受当前数据库快照与计划指定源状态完全一致；存在后续编辑、新增行或副本变化时明确停止。目标状态已经完整匹配时返回 `changed:false`，不会重复改写。

写事务设置 `lock_timeout = 5s`、单语句 `statement_timeout = 60s`，对 `station_site_drafts` 和 `user_profiles` 加 `ACCESS EXCLUSIVE` 锁。工具核实两个更新时间触发器均为原始启用状态 `O`，且绑定 `public.touch_updated_at`，再在事务中仅临时禁用这两个触发器，以保留历史时间；写完恢复并复验完整快照。异常回滚同时恢复数据与触发器。锁覆盖两张表，必须按停写维护操作执行，不做混合版本滚动迁移。

## 计划保管与命令

计划全文含私人页面及 profile 内容，应保存在服务器受限目录，目录权限 `0700`、文件权限 `0600`，禁止进入 Git、普通日志、聊天消息或公开制品。`plan` 以独占创建方式写文件并同步文件内容及父目录，不覆盖已有计划。`apply` / `restore` 拒绝符号链接、非普通文件、不符合 `0600` 的权限及超过 16 MiB 的计划。输出只包含操作、数量和摘要或错误码。

以下命令在仓库根目录执行。数据库连接 `DATABASE_URL` 和绝对计划路径 `MIAOXUN_SITE_PLAN_FILE` 由受控运行环境注入；不把连接串写在命令、仓库或日志中，不启用 shell 跟踪。先确认目录权限和正式数据库身份。

```sh
: "${DATABASE_URL:?由受控环境注入数据库连接}"
: "${MIAOXUN_SITE_PLAN_FILE:?由受控环境注入受限计划文件绝对路径}"
MIAOXUN_DOTENV_ENABLED=false node backend/scripts/migrate-site-documents.js plan "$MIAOXUN_SITE_PLAN_FILE"
```

核对汇总及摘要、完成维护前提后，使用同一计划执行：

```sh
MIAOXUN_DOTENV_ENABLED=false node backend/scripts/migrate-site-documents.js apply "$MIAOXUN_SITE_PLAN_FILE"
```

同一维护窗口内若需要恢复，且迁移后没有新写入，可用原计划：

```sh
MIAOXUN_DOTENV_ENABLED=false node backend/scripts/migrate-site-documents.js restore "$MIAOXUN_SITE_PLAN_FILE"
```

`restore` 只恢复本次页面转换，不撤销 037 数据库结构或其他业务操作。检测到后续写入时会拒绝覆盖，此时不能强行重算 hash 或改计划；应按完整数据库恢复方案评估。计划也不能替代完整备份与恢复验证。
