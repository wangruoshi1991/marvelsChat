# App 交互与设计实现复核（2026-09-16）

本轮针对蓝湖中小站、聊天、消息长按、OOTD/照片和动态卡片实现了部分通用交互。用户复核后确认整体设计仍未还原；单元测试、构建或局部模拟器验证不代表全 App 设计验收通过。本文记录局部实现和已知缺口。

## 已实现

- 根部 `AIAssistProvider` 提供统一四向内容操作层，原内容只保留一份挂载。3D 舞台、聊天消息、动态、日记和相册卡片均通过对象引用和动作契约接入。
- 长按菜单支持按住后拖向方向，也支持选择后点击动作；取消、路由变化、后台和卸载会清理异步测量与来源状态。3D WebView 关闭网页文本选择、上下文菜单和拖拽事件，不再出现系统“复制 3D”选择或克隆舞台。
- “妙管家”在所有内容类型上统一打开已有管家会话，带入标题、正文和类型作为待发送草稿；用户确认后才发送。私有媒体 URL、鉴权信息和未实现的生成结果不会写入草稿。
- 小站顶栏改为可横向滚动的 `StationTabBar`，选项按内容自然占宽，并在选择后滚动到可见位置；固定设置入口保留在右侧。
- 3D 查看器在 bridge ready 后只触发一次加载，首帧渲染后结束加载态；隐藏/后台时暂停 RAF、保留已加载场景并取消未触发的长按计时器，恢复时复用场景。App 使用移动端派生 GLB，不回退大体积原始模型。
- 第一面首次访问后保留内容树，切换时隐藏并暂停交互，避免反复重建 3D 舞台；聊天和小站路由切换会清理旧会话持有者、草稿和扫描状态。

## 设计资产结论

当前动作图标由已有妙讯管家正式图标、Agent 注册身份图标和 Lucide 语义图标组成，并通过动作 ID 显式映射。仓库目前没有蓝湖全部动作的原始 SVG 或透明 2x/3x 导出，也没有证据表明截图裁剪物可作为生产资产。要做到逐像素一致，应由设计交付每个动作的透明原图、尺寸、颜色、明暗态和授权信息，再替换 `AIAssistAction` 的 `imageSource` 映射；不能把浏览器截图抠图当作最终资源。

## 尚未闭环的产品能力

动态点赞和收藏已完成第一阶段的真实闭环：`station_post_interactions` 以用户、动态和类型为联合主键，服务端在事务中锁定动态、幂等写入/删除并回写计数；`/api/station/posts/:postId/interactions` 只接受 `like|favorite` 与显式 `active`，内容接口返回当前用户状态，所有变更写入审计事件。后台总览同步展示动态、互动、媒体资产和漫画日记的数据库计数。

音乐来自旧版默认模块，用户已明确新版设计不涉及该范围；2026-09-16 从第一面移除其展示，音乐方案暂停。最终漫画媒体仍只有分镜草稿，渲染、媒体完整性校验、发布、失败状态与后台管理属于待设计/实施流程，未部署为实际能力。

## 2026-09-18 长按边缘布局、竞态与触觉反馈修正

本轮重新逐页核对蓝湖“聊天卡片、聊天输入框、OOTD 中央触点及上/下/左/右边缘触点、照片长按”设计，修正以下实现偏差：

- 中央触点继续使用正十字布局；接近上、下、左、右边缘时，触点光圈保留在真实手指位置，四个动作按设计向屏幕内侧展开，而不是把整个十字中心强行移动。上边缘为“更多/妙管家”横向两侧及“分享/编辑”下方斜向；下边缘镜像；右边缘为“分享/编辑”纵向两侧及“妙管家/更多”左侧斜向；左边缘镜像。极窄屏和角落位置会整体平移动作组以保持标签、选中缩放和触控区完整，触点光圈不跟随平移。
- 复核后不再把标签统一放在圆下方：中央、左边缘和右边缘的分享标签在上方；上边缘四项均在下方；下边缘的分享、编辑在上方，更多、妙管家在下方。圆与标签独立计算边界，左右边缘使用横向较深、纵向较浅的扇出，上下边缘使用相反比例，避免文本把整组推离真实触点。四个动作均显示文字，包括聊天卡片顶部的“分享”。
- 四项内容按场景显式配置：聊天卡片为“分享 / 妙管家 / 复制 / 更多”，聊天输入框为“换行 / 妙管家 / 粘贴 / 更多”，3D / OOTD 和照片稿为“分享 / 妙管家 / 编辑 / 更多”。当前 3D / OOTD 已接真实系统分享，既有今日穿搭入口保留在更多菜单；聊天输入框按当前选区执行换行和剪贴板粘贴。照片稿虽已确认，但仓库还没有独立 `station-photo` 长按来源，不能将相册卡片标记为照片稿已完成。
- `AIAssistGestureSurface` 与根部 `AIAssistProvider` 分别保存来源测量和根容器测量期间的最后一次 `move/release`。3D WebView 连续发送 `activate -> move -> release` 时，不再因 React `active` 状态尚未提交而丢失移动或抬手；来源 ID 和 generation 仍用于阻止旧页面、旧来源或取消后的事件复活菜单。
- 长按菜单真正激活时触发一次 activation 反馈，首次拖入或切换到另一动作时触发轻 hover 反馈，动作真正执行时触发一次 confirmation 反馈；同一动作内重复 move 不会连续反馈。统一 JS 入口为 `features/assist/assistHaptics.ts`；iOS 注册 `MiaoxunHapticsModule`，分别使用中等 impact、selection changed、success notification；Android 注册同名模块，分别使用系统 `LONG_PRESS`、`CLOCK_TICK`、`CONFIRM`（Android 11 以下确认使用 `VIRTUAL_KEY`）。缺少原生模块时 JS 明确抛错且不提交菜单动作，不以无振动静默通过。
- 长按动作不再错误复用 `station/partners/miaoxun-assistant.png` 小站伙伴机器人头像，当前改为白色 `Bot` 语义图标，聊天列表仍使用正式人物头像 `messages/avatar-butler.png`。蓝湖长按稿中的白色产品符号尚无正式 SVG/透明 PNG，当前只解决错误身份资源，不宣称图标逐像素还原；设计交付后应通过 `AIAssistAction.imageSource` 统一替换，不能截取设计截图作为生产资源。

自动验证覆盖 320/393/768 宽度、四角与四边动作完整性、中央及四边方向映射、两段异步测量下的快速 3D 释放、重复 release 幂等、activation/hover/confirmation 反馈时机及去重、原生桥缺失时禁止误提交、取消/切页/后台清理。TypeScript、相关 Jest 和 iOS Simulator Debug 构建通过。模拟器只能验证模块注册和调用，不能证明物理触感；Android 本机缺少可用完整 JDK，本轮未完成 Gradle 原生编译。发布前仍须在真实 iPhone 和 Android 设备逐项验证反馈强度、系统“触感反馈”关闭时的行为、3D WebView 与滚动/返回手势竞争，以及四个边缘的物理拖选命中。

补充静态审查修正：拖动阈值现在也使用抬手坐标判定，避免快速拖动只收到 `release` 而没有中间 `move` 时留在菜单；不可用动作在触控和无障碍层均禁用，拖选不会发出成功触觉或误关闭菜单。相应 Jest 覆盖 RN 与 3D WebView 两段异步测量的无 `move` 抬手，以及不可用动作的点击/拖选。以上仍不能替代真机物理手势与触感验收。
