# 妙讯开发规范

## 上线目标

妙讯按正式上架产品开发。代码、文案和交互必须服务于可维护、可验证、可上线的实现，不做看起来能跑但实际不可交付的临时功能。

## 功能边界

- 未接入数据库表、后端 API、权限策略和审核流程的功能，只能展示真实空状态或不展示入口。
- 不写假聊天、假列表、假地址、假文件、假封面、假数量或假已接入状态。
- 配置缺失、权限拒绝、网络失败、后端错误必须明确提示，不静默回退到示例数据。
- 新能力先定义数据结构、接口契约、错误状态和权限边界，再接 UI。

## 代码结构

- 屏幕文件只负责页面编排、路由状态和数据传递；业务分区组件放在同 feature 目录下的独立文件。
- 一个文件持续超过约 300 行时，应优先拆分为容器、区块组件、共享组件、类型定义或服务层。
- 通用 UI 只放真正跨模块复用的组件；不要把单个业务模块的细节塞进全局共享文件。
- 业务逻辑不得混入样式文件；样式文件不得承载数据、权限或状态判断。

## 数据与状态

- 客户端只能展示后端返回的真实业务数据、本地输入中的临时状态，或明确标注的待接入状态。
- 发送中、失败、重试等本地状态必须和后端最终消息区分，不能伪装成已送达。
- Agent、虚拟形象、日记、相册、文件等长期功能必须有审计、权限和持久化方案后再做正式入口。

## 变更要求

- 删除低质量功能优先于继续包装低质量功能。
- 协议和版本不匹配时，由接口返回可定位的错误，调用方显示可执行的下一步。历史数据或已发布客户端仍有消费者时，写明支持范围、迁移办法及退出条件。
- 每次较大改动后至少执行 TypeScript 检查和 diff 空白检查。

## 模块链路与验收

- 从用户能打开的入口走到最终结果。写操作核对服务端权限、数据库事务、回执与再次进入后的真实状态。异步任务核对入队、Worker 领取、完成或取消、客户端读取成果。重试沿用同一次操作的标识，区分明确失败与结果未知。
- RN 负责业务状态，iOS 和 Android 适配系统能力。分别验证首次授权、拒绝、系统设置撤权、用户取消及 App 返回前台。单端独有的功能在入口标明可用范围。
- 运营后台和 Web 工具的列表、详情与编辑检查键盘可达、焦点返回、加载、空数据、错误和重试。限额为零、未设上限和数据缺失分别显示；统计口径以 API 合同为准。
- 页面切换或展开应保留上下文、焦点和草稿。动效表达状态变化，支持系统减少动态效果；读屏可以识别名称、角色与选中状态。记录设计依据、被修改的实际界面，以及设备、浏览器或组件测试分别覆盖了什么。[Apple 动效指南](https://developer.apple.com/design/human-interface-guidelines/motion) · [WAI 单选组交互](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) · [WCAG 键盘操作](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)
- 检查冗余时，核对 UI 入口、后端路由、Worker 和 Agent 动态注册、原生桥接、打包清单、已登记迁移及测试调用。旧 UI 仍承担测试覆盖时，先把有效断言迁到现行入口。
- 暂缓项在现有审查或交接中写明源码位置、触发条件、用户影响、当前证据和验收操作。平台尚未编译、门控测试跳过、仅组件或夹具通过时，分别标注。
