# 普通聊天附件闭环设计

日期：2026-11-16
状态：待用户审阅
范围：`MiaoxunRN/`、现有聊天附件 API、消息合同、定向测试和文档。本文不授权生产部署、TestFlight 上传或生产数据写入。

## 目标

让普通单聊和群聊可以发送静态图片与受支持的 UTF-8 文本文件，并在聊天记录中安全呈现。用户可先看到附件草稿和上传状态，确认发送后附件才成为消息的一部分；图片可全屏查看并保存到系统相册，文本文件可在应用内读取。

Agent 会话继续使用已有的 `contextRefs` / `station-photo` / `station-file` 素材合同。Agent 素材引用用于经授权的模型上下文，普通附件用于聊天收发，两者不互相转换。

## 当前合同

- 后端已有 `053_chat_attachments.sql`、`054_chat_attachment_lifecycle.sql`，并提供私有上传、结构化附件、消息引用解析和认证读取。
- 普通媒体上传最大 8 MiB；图片仅 JPEG、PNG、WebP 静态图，服务端解码后规范成 JPEG；文本文件由现有解析器限制为 UTF-8 TXT、MD、JSON、CSV、TSV，最大 256 KiB、正文不超过 50,000 字符；每条消息最多 6 个附件。
- 附件草稿按幂等键创建；发送消息时服务端再次验证附件属于当前用户及会话。读取要求附件已由本人未删除、未撤回的消息引用。删除、撤回和过期清理由现有生命周期处理。
- 当前消息 schema 要求非空正文；需改为“正文或至少一个附件”至少存在其一。数据库 `chat_messages.content` 仅要求非 NULL，当前迁移未见非空约束，因此预期无需新迁移，须由隔离 PostgreSQL 集成测试确认。
- RN 目前没有普通附件 DTO、上传服务、`attachmentIds` 发送参数或附件消息呈现。现有相册、拍摄、文件入口在 Agent 会话中上传为素材引用。

## 交互与状态

1. 普通单聊/群聊的“相册”“拍摄”“文件”选择结果进入当前会话的附件草稿区。最多 6 件，可移除；相册选择数量按剩余名额限制。文件选择只接受后端已支持的文本格式。
2. 上传在选择后立即开始，以便发送前看到已确认的服务器附件、缩略图/文件名、正在上传状态和失败状态。单项失败保留草稿并允许用户显式重试；不发送部分成功的消息。重试复用该上传的幂等键。
3. 消息可包含文字和附件，也可仅包含一个或多个附件。点发送前检查所有附件均已上传；消息发送失败保留完全相同的附件 ID 和 `clientMessageId`，按原有精确重试合同处理，不自动再次发请求。
4. 图片消息在气泡内以稳定尺寸网格/行布局呈现。点击图片进入全屏查看，可在同条多图间左右切换；保存操作只在用户点击时发起认证下载和系统相册写入。无相册授权、下载失败或设备不支持时显示明确结果，不静默失败。
5. 文件消息显示文件名、类型和大小；点击后经认证读取，在应用内文本预览中显示内容及加载/错误状态。此阶段不提供另存到文件、外部分享、视频播放或附件转发。
6. 长按菜单按消息和附件状态显示可用操作：文字保留回复/复制/删除/撤回规则；图片消息增加查看/保存入口；文件消息增加预览入口。只有真实可执行的动作才呈现。
7. 切换账号、token 或会话时，未完成的本地 picker/upload 回执不得进入新会话。服务端已上传但未引用的草稿由既有 24 小时回收机制处理；不在客户端静默扩大保留期。

## 数据流与边界

- JS/RN 负责入口选择、六件上限、草稿状态、幂等键、会话代次校验、发送和错误提示。
- 图片沿用现有 RN 本地 URI 读取与认证二进制上传模式。文件使用平台文件选择器的应用私有临时副本；iOS 复用已有 `MiaoxunDocumentPickerModule` 的隔离临时目录与重定向拦截，并增加受限的聊天上传合同。Android 若缺少对应能力，则补一个薄 SAF 文件选择/上传适配器；业务校验与状态仍由 JS 统一管理。
- 上传仅请求 `/api/threads/:threadId/attachments/upload`，发送只传服务端返回的附件 ID。认证图片/文件读取仅使用 `/api/chat-attachments/:id/content`。不接受任意远端 URL，不向重定向目标转发 Bearer token。
- 扩展已有 PhotoKit 保存适配，使其按附件 ID 从固定 API origin 读取聊天附件；不接受通用 URL。Android 使用 MediaStore；API 29+ 不申请媒体读取权限，API 24–28 仅在用户点击“保存”时请求受限的写入权限。用户拒绝或系统能力不可用时显示明确状态，不伪造成功。
- `attachmentIds` 纳入既有请求指纹、失败重试和同消息多线程投影。Direct/group 服务端 owner、thread、成员访问与撤回/删除门禁继续由现有仓库负责。
- 不改 Agent registry、Release/Product、权限 scope 或用户授权；普通附件不触发模型调用、AI 素材索引或费用。

## 主要修改边界

- RN 模型与 API：附件 DTO、普通消息发送 `attachmentIds`、二进制上传、认证内容读取和响应解析。
- RN 聊天：附件草稿区、按会话区分素材引用和普通附件、纯附件发送、图片/文件呈现、全屏查看/保存、文本文件预览及按类型筛选菜单。
- 原生薄层：文件 picker 的平台适配与图片保存到相册的聊天附件读取入口；不承载业务授权和消息状态逻辑。
- Backend：只调整消息 schema 的正文/附件互斥规则，保留既有上传/访问合同；补充 API 与重试回归测试。预期不新增数据库迁移或依赖。
- 文档：记录附件合同、限制、平台能力和错误语义；阶段实现后更新 `docs/handoffs/CURRENT.md` 与 `docs/README.md`。

## 错误与隐私

- 不支持的 MIME、损坏图片、无效 UTF-8、文件大小超限、附件过期、跨用户/会话 ID、撤回/删除后的读取，均保留后端明确错误，不转换成空附件或素材引用。
- 上传响应未知时复用同一幂等键核对，避免生成重复草稿；消息发送结果未知时只使用现有相同 `clientMessageId` 和指纹精确重试，不自动重试。
- 图片、文件正文不进入日志。API 日志只记请求 ID、路由和状态，不记录附件字节、文件正文或认证内容 URL。
- 草稿只能在所属会话发送；群聊复用服务端按成员创建的独立线程及消息副本。离群、账号切换、线程访问失效时，不允许以旧附件 ID 绕过服务端重新验证。

## 验收

- RN 单测覆盖真实上传请求头/请求体与错误解析、1–6 件限制、选择取消、逐项移除/重试、过期 picker 回执、账号/会话变化、纯附件消息、图片网格与查看器、认证文件预览、保存成功/拒绝/失败、菜单按消息类型裁剪、消息失败后精确保留附件 ID。
- Backend 回归覆盖空正文无附件拒绝、空正文有附件接受、非空正文无附件接受；Agent/UI/workspace 上下文不能借纯附件绕过各自限制；指纹包含附件 ID、重复请求及撤回/删除访问边界保持不变。
- 在隔离 PostgreSQL 上跑现有 `chat-attachments-postgres`、附件生命周期与群聊消息复制用例，确认纯附件消息及引用生命周期真实通过。
- iOS Simulator 验收相册/拍摄/文件选择、上传、发送、图片全屏/保存、文件预览、错误提示与键盘布局。Android 至少通过原生构建与文件 picker/上传适配测试；若没有可运行设备，记录为待设备验收。
- 运行 RN typecheck、目标 Jest、Backend 定向测试、`./scripts/check-repository.sh` 和 `git diff --check`。模拟器不视为 TestFlight 或真机通过。

## 暂不纳入

- 视频聊天附件：后端附件白名单、大小/存储与播放合同尚不存在。
- 录音消息：服务端识别 M4A 不代表 App 已有录音消息采集与播放闭环；现有语音是转文字草稿。
- 联系人、位置和任务结构化卡片：后端虽有类型定义，本阶段只做图片与文本文件，避免扩大交互范围。
- 自定义表情：后续按“仅本人收藏”设计独立的私有上传、持久化、删除与消息使用合同。
- 群聊客户端：下一阶段只闭合既有建群、成员读取、退出合同；不增加群成员管理接口。
- Agent 长上下文摘要：需另行定义 token 预算、摘要可见性、用户确认、撤回/删除与授权边界；当前继续明确提示上下文上限。
- 生产部署、后台发布、TestFlight 上传、生产写入、代用户授权和付费供应商调用。
