# 小站能力闭环方案

## 当前已接入

- 个人日记：`station_diary_entries` 保存手写日记，App 从 `stationContent.diaryEntries` 读取展示。
- 个人相册：`station_albums` 保存相册元数据，App 从 `stationContent.albums` 读取展示。
- 媒体资产：`station_media_assets` 保存照片元数据；后端签发 OSS 短效 PUT 上传 URL，客户端上传成功后回写 `uploaded` 状态；App 通过受保护的媒体接口读取相册封面和动态图片，由后端代理访问 OSS，避免客户端暴露签名读取 URL 或把 App 鉴权头转发给 OSS。
- 今日穿搭：`station_outfits` 保存当前 `avatar_config` 快照，App 从 `stationContent.outfits` 读取展示。
- 我的动态：App 从真实日记、相册、照片和穿搭内容聚合生成动态流，不展示示例点赞、评论或假媒体。
- 小站 3D 形象：App 原生完成照片检查、参数与授权、任务轮询、四视图确认和模型管理；小站舞台只用受限 WebView 显示指定的私有 GLB，不嵌入完整 Web 工作台。
- 小站首页：只展示个人内容和少量自然入口，不直接承载建站、相册整理、素材预处理、视频制作等 Agent 操作面板；3D 生成是独立产品流程，不属于 Agent 工作区。
- AI伙伴：负责 Agent 添加/移除、助理对话入口和跨模块能力工作区；工作区只展示用户已添加的能力。

## 虚拟人物定位

虚拟人物不能只做一个低模形象编辑器。正式方案应拆成四层：

1. 资产层：授权角色模型、贴图、衣物、配饰、动作、压缩版本和资源版本记录。
2. 配置层：用户当前形象配置、穿搭快照、素材引用、可见范围。
3. Agent 层：形象顾问只能给建议；任何写入必须生成明确 action，经用户确认后写数据库。
4. 展示层：小站舞台只读取配置和资产，不在前端生成假素材。

## 四个按钮闭环

| 按钮 | 当前行为 | 正式闭环 |
| --- | --- | --- |
| 今日穿搭 | 保存当前 `avatar_config` 快照到 `station_outfits` | 接衣物素材库、OOTD 媒体、审核和公开可见范围 |
| 漫画日记 | 从日记详情生成漫画分镜草稿 | 接图片资产生成、审核和公开可见范围 |
| AI伙伴 | 进入 Agent 管理和能力工作区 | 接用户授权状态、调用范围、调用审计和公开调用入口 |
| 可被调用 | 进入 Agent 管理和调用范围说明 | 接公开权限、速率限制、调用记录和被调用通知 |

小站首页模块使用明确的双入口：个人日记绑定已注册的 `comic-diary`，个人相册绑定已注册的 `album-manager`；Agent 已添加时进入对应对话，未添加时进入 AI伙伴管理。“更多”进入该模块按月份分组的完整内容列表，列表项点按查看详情、左滑快捷编辑。AI伙伴模块由具体伙伴进入对话，不额外创建不存在的总管 Agent。

首页摘要网格不生成占位内容：日记最多 4 条、相册最多 3 个、AI伙伴最多 6 个；日记和伙伴固定两列，相册固定三列，单数末项保持原列宽并靠左排列，零数据使用模块空状态。

个人日记、个人相册的创建、详情和编辑入口统一进入全屏内容工作区。首页创建返回首页，列表内创建返回列表；日记使用纯文本编辑器，相册创建必须选择照片并在一次保存动作中完成建册和上传。上传失败时先清理对象存储，再删除新相册，不保留半成品。旧 `pageSheet` 仅保留给今日穿搭等独立流程。

小站新版顶层导航为“第一面 / 生活 / 成果 / 生态 / 其他”。动态发布入口位于生活页的“正在发生”区域；成果只读取真实动态和 Agent 产出数量，不显示设计稿中的示例收入或评分；既有社交关系归入其他。底部导航仅保留“妙讯 / 小站”，不再放置中央发布按钮。

小站不使用覆盖页面内容的悬浮球。内容级 AI 辅助由具体模块自己的长按交互承载；妙讯管家通过真实会话或 Agent 卡片进入。主页面浅色视觉统一使用 `#F8F7FD` 页面底色、`#FFFFFF` 内容板块、`#F4F6FF` 辅助底色、`#F0EBFD` 分隔色和 `#2012D9` 强调色。

日记详情的“漫画分镜”调用真实 `comic-diary` Agent。模型返回值必须通过结构化 JSON、指定帧数、文本安全和媒体归属校验后才写入 `station_comic_diaries`。当前 Agent 只生成可审查的分镜结构，不声称已经生成最终漫画图片；最终出图仍属于后续图片生成能力。

日记详情发起的直接 Agent 调用与聊天 Agent 一样写入 `agent_runs`，记录成功/失败、Provider、耗时和 Token 使用；业务内容与调用审计分开持久化。

## 下一步上线任务

- 验证正式 OSS AccessKey：当前代码链路已接入，发布预检必须确认服务器已设置 `OSS_ACCESS_KEY_ID` 和 `OSS_ACCESS_KEY_SECRET`；任一缺失时接口会明确返回 503。
- 接媒体审核：上传后先进入待审核，审核通过后相册才公开展示。
- 接 Agent 写入动作：日记生成、穿搭建议、形象方案必须写 `agent_runs`，并由用户确认后落表。
- 接公开主页读取：按 `profile_visibility` 和内容可见范围返回他人可见的小站内容。
