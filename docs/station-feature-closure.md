# 我页与创作能力闭环

更新：2026-10-15。本页描述当前工作区能力与未完成边界；正式部署和真机验收状态见[当前交接](handoffs/CURRENT.md)。原小站代码仍位于`features/station`，当前产品入口为“我”。

## 当前已接入

- 个人身份资料：职业身份、主动展示的城市、经验年限、语言、签名在 App / 数据库 / 公开资料 / 后台有同一契约。详情与发布依赖见[2026-09-16 资料闭环](reviews/2026-09-16-profile-identity.md)。合作伙伴与评分已经确认按完成合作/评价计算，[完整流程](reviews/2026-09-16-cooperation-lifecycle.md)仍待实现，不混用关注或 Agent 计数。

- 个人日记：`station_diary_entries` 保存手写日记，App 从 `stationContent.diaryEntries` 读取展示。
- 个人相册：`station_albums` 保存相册元数据，App 从 `stationContent.albums` 读取展示。
- 相册检索：保留对真实文件名、说明和用户标签的文字查找；已删除按预置关键词/文件名猜标签、固定分组和虚构置信度的建议接口。用户显式标签不再被去标点或改写空格，上传不自动推标签。相册Agent的视觉检索仍通过独立授权的真实视觉索引执行，不依赖旧建议规则。
- 文字素材：文件登记接口只保存类型、字节数、哈希、字符/行数和最多1000字符的原样预览，不保存完整原文或执行AI理解。入口无示例内容，只调用一次登记接口；原重复预处理接口及客户端链路已删除。预览通过原生纯文本展示，保留标签、空白和换行；已有记录继续读取，不改写历史数据。模型摘要使用`text.summarize`处理明确聊天文字/文字成果，登记文件到摘要的链路尚未接通。
- 媒体资产：`station_media_assets` 保存照片元数据；后端签发 OSS 短效 PUT 上传 URL，客户端上传成功后回写 `uploaded` 状态；App 通过受保护的媒体接口读取相册封面和动态图片，由后端代理访问 OSS，避免客户端暴露签名读取 URL 或把 App 鉴权头转发给 OSS。按媒体 ID 读取也校验站主活跃状态、主页开关及动态/相册可见范围，受保护文件不使用长期不可变缓存；因此高频展示需要后续以有授权边界的缩略图/版本化媒体方案优化性能。
- 今日穿搭：`station_outfits` 保存当前 `avatar_config` 快照，App 从 `stationContent.outfits` 读取展示。
- 我的动态：App 从真实日记、相册、照片和穿搭内容聚合生成动态流，不展示示例点赞、评论或假媒体。
- 点赞/收藏：动态交互事务同时校验站主状态、展示开关、公开/好友范围，并在同一事务内写意图、计数和审计；关闭展示或撤销好友后，已知动态 ID 也不能继续互动。
- 小站 3D 形象：App 原生完成照片检查、参数与授权、任务轮询、四视图确认和模型管理；小站舞台只用受限 WebView 显示指定的私有 GLB，不嵌入完整 Web 工作台。
- 小站首页：只展示个人内容和少量自然入口，不直接承载建站、相册整理、素材预处理、视频制作等 Agent 操作面板；3D 生成是独立产品流程，不属于 Agent 工作区。
- AI伙伴：在“我 → 生态”负责 Agent 添加/移除、助理对话入口和能力工作区；添加时一次确认完整声明权限，相册云端同意合并在同次确认中。没有逐相册重复授权，不为已有不完整授权自动补权；任务执行和数据读取仍按账号、明确来源及当时权限校验。

## 虚拟人物定位

虚拟人物不能只做一个低模形象编辑器。正式方案应拆成四层：

1. 资产层：授权角色模型、贴图、衣物、配饰、动作、压缩版本和资源版本记录。
2. 配置层：用户当前形象配置、穿搭快照、素材引用、可见范围。
3. Agent 层：形象顾问只能给建议；任何写入必须生成明确 action，经用户确认后写数据库。
4. 展示层：小站舞台只读取配置和资产，不在前端生成假素材。

| 可被调用 | 进入 Agent 管理和调用范围说明 | 接公开权限、速率限制、调用记录和被调用通知 |

小站首页模块使用明确的双入口：个人日记绑定已注册的 `comic-diary`，个人相册绑定已注册的 `album-manager`；Agent 已添加时进入对应对话，未添加时进入 AI伙伴管理。“更多”进入按月份分组的列表，列表项点按查看详情、左滑快捷编辑。当前列表仍复用 bootstrap 的最近 20 条日记/20 个相册，尚未实现历史分页，不能视为完整内容列表；详见 [2026-09-15 审查](reviews/2026-09-15-repository-audit.md)。AI伙伴模块由具体伙伴进入对话，不额外创建不存在的总管 Agent。

首页摘要网格不生成占位内容：日记最多 4 条、相册最多 3 个、AI伙伴最多 6 个；日记和伙伴固定两列，相册固定三列，单数末项保持原列宽并靠左排列，零数据使用模块空状态。

个人日记、个人相册的创建、详情和编辑入口统一进入全屏内容工作区。首页创建返回首页，列表内创建返回列表；日记使用纯文本编辑器，相册创建必须选择照片并在一次保存动作中完成建册和上传。上传失败时先清理对象存储，再删除新相册，不保留半成品。旧 `pageSheet` 仅保留给今日穿搭等独立流程。

底部导航为“妙 / 讯 / 我”，默认进入妙页；我页内部导航为“第一面 / 生活 / 成果 / 生态 / 其他”。动态发布入口位于生活页的“正在发生”区域；既有社交关系归入其他。成果页聚合真实页面、协作文字、漫画分镜、已有视频草稿和穿搭记录，卡片可打开对应任务、受保护页面预览或正文，不显示示例收入、评分或用静态计数代替成果入口。待确认页面进入拥有该草稿的任务完成预览与确认；相同页面按ID去重。当前只覆盖已加载的最近内容与任务，尚无完整历史分页，成果续作仍未完成。

我页不使用覆盖页面内容的悬浮球。内容级 AI 辅助复用共享长按手势，相册首页与二楼共用`AlbumContextActions`定义同一组动作；妙讯管家通过真实会话或 Agent 卡片进入。产品颜色集中在`shared/theme.ts`，工作区和各页面通过语义调色板消费；这只减少重复定义，不代表逐页布局和设计还原已经验收。

日记详情的“漫画分镜”调用真实 `comic-diary` Agent 的`plan`。模型必须返回一个完整JSON对象，所有约定字段、指定格数、文本长度和所选媒体引用均通过校验后才写入`station_comic_diaries`。缺少标题/摘要/分镜字段、围栏或混合文字、超长内容、重复或越界媒体引用直接失败；服务不补内容、不截断、不夹取JSON。只有用户省略风格/格数时才使用生活漫画/4格默认值，显式无效值不会被替换。独立聊天使用自然文字，协作`comic.storyboard`交付可读文本，不套此保存结构。当前未生成最终漫画图片。

日记详情发起的直接 Agent 调用与聊天 Agent 一样写入`agent_runs`。授权和所选来源在调用前、保存前重验，成功审计和分镜保存处于同一事务；公共结果不携带模型审计元数据。视频只通过会话及`video.script`协作能力提供文字脚本；已移除不可用的生成接口与面板，已有视频草稿继续可读，未接最终视频生成与渲染。
